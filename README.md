# Практическая работа по конфигурационному управлению
## Вариант №11 — эмулятор командной оболочки с виртуальной файловой системой

Реализованы **все пять этапов**: REPL → конфигурация → ZIP-VFS → основные команды → удаление в памяти. Язык: **Python 3.10+**, только стандартная библиотека. Можно запускать на Windows, Linux и macOS.

## 1. Быстрый запуск на Windows

1. Установите Python 3.10+ с https://www.python.org/downloads/ (при установке отметьте **Add python.exe to PATH**) и распакуйте архив проекта.
2. Откройте папку проекта в VS Code: **File → Open Folder**. Откройте терминал: **Terminal → New Terminal**.
3. В корневой папке, где находится `main.py`, выполните:

   ```powershell
   python main.py --vfs demos/demo_vfs.zip
   ```

   Если команда `python` недоступна, попробуйте `py -3 main.py --vfs demos/demo_vfs.zip`.

4. Программа показывает приветствие из `/motd` и приглашение `VFS:/$`. Вводите, например:

   ```text
   ls
   ls -al
   cd docs/tutorial
   pwd
   cat intro.txt
   cd advanced
   cat tips.txt
   cd /
   who
   uptime
   conf-dump
   rm notes/todo.txt
   ls notes
   exit
   ```

5. **После нового запуска** файл `/notes/todo.txt` будет снова доступен, потому что ZIP остаётся неизменным.

Путь к своему ZIP можно указать в кавычках:

```powershell
python main.py --vfs "C:\Users\student\Desktop\my archive.zip"
```

Для работы с виртуальными путями внутри VFS используются прямые слеши `/`, как в UNIX.

## 2. Работа со стартовыми сценариями

Для выполнения последовательности команд из текстового файла укажите `--script`. Программа выводит команды вместе с результатами. Первая ошибка прерывает скрипт и возвращает ненулевой код:

```powershell
python main.py --vfs demos/demo_vfs.zip --script demos/stage4_success.vfs --batch
```

`--batch` — дополнительное удобство: после скрипта программа завершается, а не переходит в интерактивный REPL. Без этого флага после успешного сценария можно вводить команды вручную (если в сценарии не было `exit`).

Команда `conf-dump` выводит настройки `vfs=...`, `script=...`, `batch=...` в формате *ключ=значение*.

### Готовые сценарии по этапам

| Файл | Что показывает |
|---|---|
| `demos/stage2_ok.vfs` | Параметры командной строки, `conf-dump`, `ls`, `cd` |
| `demos/stage2_error.vfs` | Неизвестная команда → прерывание сценария |
| `demos/stage3_minimal.vfs` | Минимальная VFS без `motd` |
| `demos/stage3_nested.vfs` | Глубокая вложенность каталогов |
| `demos/stage4_success.vfs` | `ls`, `ls -a`, `ls -l`, `cd`, `cat`, `who`, `uptime`, `pwd` |
| `demos/stage4_error.vfs` | Ошибка чтения несуществующего файла |
| `demos/stage5_success.vfs` | `rm` (обычный, `-r`, `-f`, `-rf`) |
| `demos/stage5_error.vfs` | Ошибка удаления каталога без `-r` |

### Реальные OS-скрипты

- **Windows:** запустите `scripts\test_all.bat` из терминала/Проводника (при наличии Python в `PATH`).
- **Linux/macOS:** `bash scripts/test_all.sh`.

Скрипты запускают эмулятор с разными комбинациями `--vfs` и `--script`, проверяют несколько ZIP, корректные и ошибочные случаи, после чего вызывают автоматические тесты.

## 3. Поддерживаемые команды

| Команда | Назначение и режимы |
|---|---|
| `ls [путь...]` | Список файлов/папок в ZIP; `-a` — включая скрытые; `-l` — тип и размер в байтах; `-al` и `-la` — сочетание опций |
| `cd [путь]` | Перейти в виртуальный каталог; `cd` — в `/`; `cd ..` — уровнем выше; `cd -` — в предыдущий каталог |
| `pwd` | Показать текущий виртуальный путь |
| `cat файл...` | Вывести содержимое одного или нескольких файлов; `-n` — с номерами строк |
| `uptime` | Время работы **эмулятора** с запуска |
| `who` | Упрощённая имитация сеанса: пользователь ОС, терминал `vfs`, время старта |
| `rm файл...` | Удалить файлы **только из RAM**; `-r` — рекурсивно каталоги; `-f` — без ошибки, если путь отсутствует; `-rf` — вместе |
| `conf-dump` | Вывести значения всех настроек в виде `ключ=значение` |
| `echo текст...` | Распечатать переданные аргументы; удобно проверять `$HOME` и другие переменные реальной ОС |
| `help` | Справка |
| `exit` | Завершить работу оболочки |

Поддерживаются абсолютные и относительные пути, `.` и `..`, аргументы в кавычках и подстановка переменных окружения через `$NAME` или `${NAME}` (например, `echo $HOME`). Реализован учебный **эмулятор**, а не полноценный Bash: нет конвейеров, перенаправления вывода или произвольных внешних команд. Содержимое текстовых файлов выводится как UTF-8; нетекстовые байты при `cat` могут отображаться символом замены.

## 4. Внутреннее устройство

```text
main.py
  └─ vfs_shell/shell.py
       ├─ argparse: --vfs, --script, --batch
       ├─ REPL + парсер команд (shlex)
       ├─ запуск сценария (остановка при первой ошибке)
       ├─ ls / cd / pwd / cat / who / uptime / rm
       └─ vfs_shell/vfs.py
            ├─ чтение ZIP через zipfile
            ├─ dirs: set[str] (папки)
            ├─ files: dict[str, str] (байты в base64)
            ├─ разрешение виртуальных путей
            └─ удаление узлов только из словарей и множеств
```

Исходный ZIP **не извлекается на диск и не перезаписывается**. При запуске его содержимое считывается из архива и сохраняется в оперативной памяти. Если в ZIP есть `motd` в корне, его содержимое печатается до приглашения ко вводу. Директории определяются и из явных ZIP-записей, и из путей вложенных файлов.

Для генерации примеров ZIP выполните:

```powershell
python demos/create_demo_vfs.py
```

Поставляются готовые `demo_vfs.zip`, `minimal_vfs.zip`, `nested_vfs.zip` и специально повреждённый `invalid_vfs.zip`.

## 5. Автоматические тесты

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют загрузку ZIP, бинарные данные в base64, вложенность, виртуальные пути, режимы команд и аргументы, `motd`, ошибки скриптов, ошибочные архивы и то, что `rm` не меняет исходный ZIP. **Нет сторонних зависимостей** (`pip install` не нужен).

## 6. История Git и сдача работы

В составе проекта сохранена папка `.git` с **отдельными коммитами для каждого этапа**, оформленными в стандартном стиле:

1. `feat(stage-1): ...` — REPL
2. `feat(stage-2): ...` — конфигурация
3. `feat(stage-3): ...` — ZIP-VFS
4. `feat(stage-4): ...` — основные команды
5. `feat(stage-5): ...` — удаление в памяти, тесты, документация

Проверить историю из папки проекта:

```powershell
git log --oneline
```

Если преподаватель требует именно **удалённый Git-репозиторий**, нужно создать пустой репозиторий в GitHub/GitLab и самостоятельно выполнить из папки проекта (заменив URL своим):

```powershell
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

В архиве локальная Git-история уже есть; автоматическая отправка на чужой аккаунт не производилась.
