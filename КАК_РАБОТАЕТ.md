# Объяснение практической работы — вариант №11

## Основная идея

Задача — сделать миниатюрную копию терминала UNIX, которая исполняет **только свои учебные команды** и работает с **виртуальной** файловой системой из ZIP-архива. Это не командная оболочка операционной системы: `cd` не меняет физическую текущую папку Windows, `ls` не читает настоящий диск, `rm` не удаляет реальные файлы.

**REPL** расшифровывается как Read → Evaluate → Print → Loop: программа ждёт команду, разбирает её, выполняет, показывает результат и снова приглашает к вводу. Например:

```text
VFS:/$ ls
README.txt
docs/
notes/
VFS:/$ cd docs/tutorial
VFS:/docs/tutorial$ cat intro.txt
Введение в виртуальную оболочку.
```

Пример сокращён: реальные списки включают и другие файлы.

## Что выполнено в каждом этапе

### Этап 1. REPL

Создан цикл ввода. В приглашении присутствует `VFS`. Команды разделяются на имя и аргументы с помощью `shlex`, понимаются кавычки; значения `$HOME` и других переменных подставляются из окружения настоящей ОС. `ls` и `cd` сначала были заглушками; `exit` заканчивал цикл. Если имя команды неправильное или синтаксис аргументов ошибочен, выдаётся сообщение.

### Этап 2. Настройки

Программа получила параметры `--vfs` (адрес ZIP) и `--script` (путь к стартовому сценарию). `conf-dump` показывает текущие настройки. Сценарий — обычный текстовый файл: по одной команде на строку; команды и результаты печатаются на экран. При первой ошибке сценарий останавливается. Дополнительная опция `--batch` нужна для удобной автоматической проверки.

### Этап 3. VFS

При запуске `zipfile.ZipFile` читает ZIP, но **не распаковывает его в папку**. Дерево хранится в Python:

```python
self.dirs = {"/", "/docs", "/docs/tutorial", ...}
self.files = {"/docs/tutorial/intro.txt": "...base64...", ...}
```

Каждый файл физически представлен текстом base64, полученным из исходных байтов. Например, `b'Hi'` превращается в `SGk=`. При `cat` происходит обратная операция — `base64.b64decode`. Если в архиве есть `/motd`, программа автоматически печатает его при запуске. Предусмотрены ошибки отсутствующего, повреждённого и некорректного ZIP.

### Этап 4. Основные команды

`ls` читает виртуальные словари и показывает файлы и папки; `ls -al` дополнительно показывает скрытые имена, тип и размер. `cd` обновляет переменную `cwd` (текущий виртуальный каталог), а не физическое расположение процесса. `cat` извлекает содержимое файлов из памяти. `uptime` считает время от запуска процесса; `who` показывает условную запись о сеансе эмулятора с настоящим именем пользователя ОС.

### Этап 5. Удаление

`rm` убирает файл из словаря `self.files`. `rm -r` рекурсивно удаляет каталоги и вложенные файлы из структур в памяти. `rm -f` подавляет ошибку отсутствующего пути. Запись обратно в ZIP **никогда не выполняется**, поэтому перезапуск возвращает исходное состояние. Для безопасности заблокировано удаление корня VFS и текущего каталога (либо его предков).

## Показ преподавателю — 3–5 минут

1. Открыть терминал в корне проекта и выполнить `python main.py --vfs demos/demo_vfs.zip`. Показать приветствие и строку `VFS:/$`.
2. Ввести `conf-dump`, `ls -al`, `cd docs/tutorial/advanced`, `pwd`, `cat tips.txt`, `who`, `uptime`.
3. Ввести ошибочную команду `incorrect`; увидеть сообщение и убедиться, что интерактивный режим продолжает работать.
4. Вернуться командой `cd /`, выполнить `rm notes/todo.txt`, затем `ls notes`. Файл исчез.
5. Выполнить `exit`, запустить приложение заново и проверить `ls notes`: файл вернулся, потому что ZIP не менялся.
6. Запустить `python main.py --vfs demos/demo_vfs.zip --script demos/stage4_error.vfs --batch`: сценарий останавливается на ошибке, последующие строки не выполняются.
7. Запустить `python -m unittest discover -s tests -v` и `git log --oneline` — видны проверки и поэтапные коммиты.

## Типичные вопросы преподавателя

**Чем виртуальная ФС отличается от обычной?** Виртуальная система существует как модель из данных Python. Физический диск не изменяется; пути `/docs/...` относятся только к модели.

**Зачем ZIP, если можно просто читать файлы из папки?** Это требование задания и удобный способ хранить единый исходный снимок файловой системы. Чтение ZIP позволяет строить дерево целиком в RAM и гарантирует, что `rm` не повлияет на оригинал.

**Почему нужен base64?** Это текстовое представление произвольных двоичных байтов. Словарь может хранить и текстовые, и двоичные файлы в одинаковом формате.

**Чем отличается REPL от стартового скрипта?** REPL ждёт новые команды пользователя; скрипт читает уже записанные команды из файла. Оба режима используют одни и те же обработчики.

**Что происходит с `cd`?** Изменяется переменная `cwd` внутри экземпляра Shell. Для дальнейших относительных путей используется именно это значение.

**Почему удалённый файл возникает снова после перезапуска?** Меняется только словарь файлов в памяти. При новом запуске данные заново загружаются из неизменённого ZIP.

**Почему `rm /docs` без `-r` вызывает ошибку?** Поскольку `/docs` — каталог. Для рекурсивного удаления нужен `rm -r /docs`, как в UNIX-подобных оболочках.

**Что произойдёт при ошибке в скрипте?** Напечатается сообщение с номером строки, выполнение остановится, процесс получит ненулевой код возврата.

**Это полноценный Bash?** Нет. Здесь реализован определённый учебным заданием набор встроенных команд. Конвейеры, программы ОС и сложная грамматика shell намеренно не поддерживаются.

**Где история изменений?** В локальной папке `.git`: каждый этап выделен отдельным коммитом. `git log --oneline` показывает пять этапов.
